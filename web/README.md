# Counterparty Risk - web

Angular front end of the counterparty risk dashboard (issue #12): workspace, corporate design
system and front CI. The widgets W1-W12 come with #13 and are assembled from the shared table and
chart kit of #14 (see below).

## Stack

| Item | Version |
| --- | --- |
| Node.js / npm | 26 (`.nvmrc`) / 11.4.2 |
| Angular (standalone, signals, zoneless, OnPush, strict) | 22.2 |
| Angular Material (M3 theme, density -2) | 22.2.6 |
| Tailwind CSS (layout only, no preflight) | 4.3.4 |
| AG Grid Community / Highcharts | 36.3.0 / 13.1.1 (see `THIRD_PARTY_LICENSES.md`) |
| Unit tests | Vitest 5 + jsdom + `@testing-library/angular` |

## Commands

```bash
npm ci                 # install from the lockfile
npm start              # dev server on http://localhost:4200
npm run lint           # ESLint (angular-eslint + security rules)
npm run test:ci        # unit tests, single run, coverage in coverage/
npm run build          # production build in dist/
npm run check:contrast # WCAG 2.1 AA contrast of the design tokens
npm run check:licenses # licence allow-list on package-lock.json
npm run serve:csp      # serve dist/ under the target CSP (http://127.0.0.1:4300)
```

Unit tests run with the Angular CLI default runner, **Vitest in a jsdom environment**: no browser
is needed, locally or in CI.

## Folder structure

```
src/
  app/
    core/         # cross-cutting services (theme today; auth, http, config in #13)
    layout/       # shell: top bar + side navigation W1-W12
    shared/       # ui, grid (#14), charts (#14), format pipes
    features/     # home, widget pages (w01-... in #13)
  styles/         # design system (tokens, dark theme, Material theme, typography)
  tailwind.css    # Tailwind layers (theme + utilities, no preflight)
  styles.scss     # global entry point

```

## Design system

- `src/styles/_tokens.scss`: CSS variables `--cr-*` (light theme and shared tokens).
- `src/styles/_dark.scss`: dark values, applied by `prefers-color-scheme: dark` unless the user
  forced light, or by `data-theme="dark"` on `<html>`.
- `src/styles/_material-theme.scss`: `mat.theme()` with the navy palette
  (`_theme-colors.scss`, generated by `ng generate @angular/material:theme-color`),
  `theme-type: color-scheme` and system tokens overridden by the `--cr-*` tokens.
- `src/styles/_typography.scss`: Inter (self-hosted), `.cr-numeric` (tabular figures),
  `.cr-text-muted`, `.cr-page-title`.
- Theme switch: `ThemeService` (system, light, dark) in the top bar.

Use colors only through the tokens (`var(--cr-...)` or the Tailwind aliases `bg-cr-surface`,
`text-cr-text-muted`, ...). Status tokens (`--cr-status-*`) and chart series meet 3:1 for
non-text elements; for text, use `--cr-color-text` or `--cr-color-text-muted` (4.5:1).

### Tailwind and Material

The root font size stays at the browser default (100 %), so the browser text-size setting is
respected; compactness comes from density -2 and component typography overrides.

Tailwind is for layout only (grid, flex, spacing). Its preflight is not loaded, and all its rules
live in cascade layers: unlayered Material styles always win, so a utility can never break a
Material component. Style Material components with their `mat.*-overrides()` mixins, not with
Tailwind classes.

## Shared tables and charts (#14)

Widgets never use the AG Grid or Highcharts API directly (ESLint `no-restricted-imports`): they
assemble the components of `src/app/shared`, whose typed inputs enforce the EDB rules.

| Component | Use |
| --- | --- |
| `app-data-grid` (`shared/grid`) | AG Grid Community: typed columns `money` (EUR m), `percent`, `bps`, `integer`, `date`, `lei`, `text`, `status`; sort, filters, pinned column, pagination; thresholds (80 % / 100 % by default) as CSS classes plus a text marker; export through `POST /api/v0/exports` (#31), client CSV with formula neutralisation in mock mode only |
| `app-waterfall-chart` | Waterfall steps `start` / `delta` / `subtotal` / `total` |
| `app-line-chart` | Multi-series lines, `rebase100`, limit lines, event markers |
| `app-stacked-bar-chart` / `app-grouped-bar-chart` | Stacked (`normal` / `percent`) or side-by-side bars |
| `app-horizontal-bar-chart` | Bars coloured by threshold (limit utilisation, CS01) |
| `app-pareto-chart` | Top N share and cumulative share on one percentage axis |
| `app-kpi-tile` (`shared/ui`) | KPI value, level, D-1 / M-1 variations, status, link |

Rules enforced by construction:

- `title` and `level` are required inputs; the displayed title is `<title> - <exposure level>`
  (`'NotAnExposure'` must be stated for ratios, spreads and indices, never for amounts).
- Each series carries its `family` (mirror of `Domain.Contracts/Measures`, #5): economic and
  regulatory series in one chart, or a published benchmark with recomputed figures, are refused
  (`ChartRuleError`): the chart is not drawn, the reason is logged and shown in development.
- One Y axis only: series of different units require `rebase100`. No pie or donut component
  exists, and ESLint fails on `type: 'pie'`, `variable-pie` imports and `yAxis: [...]`.
- Highcharts sits behind the `ChartAdapter` (`shared/charts/highcharts`, ADR-001 §6): `styledMode`
  (colours from the tokens, no inline style), `useHTML: false` everywhere, every label escaped
  (untrusted GLEIF names), single-line text tooltips, `credits` on, accessibility module with a
  description, and an HTML data table under each chart. The exporting modules are not loaded.
- `/dev/catalog` shows every component on synthetic data in development builds only (the route
  is removed from production builds).
## Security rules

- **No DOM XSS sinks.** ESLint fails on `innerHTML`, `outerHTML`, `insertAdjacentHTML`,
  `document.write` (on any object), `bypassSecurityTrust*`, `Renderer2.setProperty` on these
  sinks, their computed forms (`el['innerHTML']`), `eval`, `new Function`, `[innerHTML]` /
  `[outerHTML]` / `[srcdoc]` bindings and inline styles in templates.
- **No sensitive data in web storage.** `localStorage` / `sessionStorage` are forbidden by
  ESLint everywhere except `core/theme`, which stores the theme preference only. Tokens stay in
  the BFF session cookie (#9); never store a token, identifier or business data in the browser.
- **No third-party resource at runtime**: fonts are bundled, no CDN, no Highcharts export server.
- `src/environments` must never contain secrets or IdP URLs: runtime configuration comes from the
  BFF.

### Content Security Policy and Trusted Types

The production build contains **no inline script**: `index.html` only loads `main-*.js` with
`<script type="module" src>`. Critical CSS inlining is disabled, so there is no inline style
either. The CSP header is set by the BFF (#10), which must, for each request of `index.html`:

1. generate a random nonce (at least 128 bits),
2. replace every `CSP_NONCE_PLACEHOLDER` in `index.html` with it (used by `ngCspNonce` for the
   styles that Angular and Material inject at runtime),
3. send this header:

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'nonce-<nonce>';
  font-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self';
  form-action 'self'; frame-ancestors 'none'; require-trusted-types-for 'script';
  trusted-types angular
```

`npm run build && npm run serve:csp` reproduces this behaviour locally
(`scripts/serve-csp.mjs`). The home page and the widget routes load with **no CSP or Trusted
Types violation** under this policy (checked with headless Chrome).

Why `autoCsp` is not enabled: its inline loader assigns `script.src` from a plain string, which
`require-trusted-types-for 'script'` blocks (`This document requires 'TrustedScriptURL'
assignment`). With no inline script at all, `script-src 'self'` is stricter than hashes and keeps
Trusted Types enforceable with the single `angular` policy. Subresource Integrity is also off
because it adds an inline import map; all assets are same-origin.
